# 实机校准指南 —— STAC 消费侧只读桥 v0.1 校准与收紧

这是一份结果式校准指南，交给在真实 STAC 目录上执行校准
的 AI Agent：只描述要达成的结果、验收标准与红线，具体
做法由执行者决定；但每一步的原始输出必须留档回传，没有
JSON 原文的回报视为未执行。

前置环境：一个可达的真实 STAC API 目录（优先选支持
GET /search 的公开目录，如 Microsoft Planetary Computer、
Earth Search 或 Copernicus Data Space 的 STAC 端点；具体
可用性以校准当日实测为准），一个内容已知的集合（能预先
用目录方自己的检索界面核对条目数与首条属性）。校准机上
先跑通 `live/selftest.py`（协议自检 13/13）再进入实机
步骤——自检不过，先修协议层，不许往下走。

## 目标结果（全部达成才算完成）

1. probe_api.py 在目标目录全绿：落地页 id 落档，集合
   计数与目录官方界面（或原始 /collections 响应）一致
   （ready=true）。
2. 集合对账通过：list_collections 的 id、许可与时空
   范围与原始 /collections JSON 逐项一致；get_collection
   对一个已知集合的许可与范围与原始集合文档一致。
3. 检索对账通过：对一个已知集合＋已知 bbox，
   search_items 的条目数与首条的 datetime、云量与目录方
   检索界面（或原始 /search 响应）逐条一致；limit 截断
   行为真实成立（limit=1 只回 1 条）。
4. 导出对账通过：导出的 GeoJSON 能在 QGIS 打开，足印
   位置与目录条目几何一致，features 数与同条件检索
   count 一致。
5. 负例口径成立：错 token → BAD_TOKEN；limit 超上限 →
   LIMIT_EXCEEDED；不存在的集合 id → 结构化 HTTP_ERROR
   （404）；需要 Key 而未配的目录 → 401/403 如实回报，
   不绕认证。
6. 校准结论回写 README「状态声明」：目录名与访问日期、
   逐项结果、与模板的差异点（特别是 GET /search 支持
   情况与 next 链接形态）；selftest 保持全 PASS。

## 校准顺序（不要跳步）

1. **先 ping + discover**：完整回传两份 JSON 原文。
   ping 不通就停在这里，先解决地址/网络/认证，不许
   往下走。注意：某些环境（如受限出网的 VM）连不通
   公开目录是环境问题，不要据此宣称目录不可用，换到
   可出网环境再校准。
2. **集合对账**：对同一目录分别用桥与 curl（或浏览器）
   取原始 JSON，逐项核对集合清单与一个集合详情；
   差异逐条记录。
3. **检索对账**：选一个数据已知的集合与范围，桥的检索
   结果与原始 /search 响应逐条核对；云量字段注意各
   目录 eo 扩展的口径差异（有的目录云量在条目属性、
   有的在集合级摘要），记录原文不擅自换算。
4. **导出验收**：导出 GeoJSON，在桌面 GIS 打开核对
   足印与 features 数；核对导出文件 properties 里的
   note 口径（不含影像本体）与实际一致。
5. **负例验证**：按目标结果第 5 条逐项执行并留档。
6. **收紧与回归**：按实机差异改代码/文档口径（只许
   收紧，不许放宽硬上限来“适配”），跑 selftest，改动
   逐条回传。

## 红线

- 校准全程只许 GET 只读请求；不许为了对账去下载大体量
  资产或批量检索（检索 limit 用小值），更不许对目录做
  任何写操作。
- API Key 只经环境变量，不许出现在任何回传、日志或
  文件里。
- 对账参照值必须来自桥之外的独立来源（目录原始响应、
  目录方检索界面）；拿桥自己的输出对账等于没校准。
- 一个目录校准通过只说明该目录；换目录（尤其换实现，
  如从 stac-fastapi 换到其他实现）须重新走检索对账，
  不许把结论跨目录套用。
- 任一步对不上：停在该步、回传差异，不许改判定口径
  凑绿。
