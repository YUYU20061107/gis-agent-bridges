## 〇、通用化落地为四条施工规则

| # | 规则 | 含义 |
|---|---|---|
| R1 | **契约先行** | 每个动词先定跨后端语义契约（语义、参数、默认值、单位、CRS、容差、错误语义），各后端实现向契约对齐，不向任何一家平台的原生行为对齐。 |
| R2 | **通用骨架＋薄适配** | 实现按能力族共用骨架，每家后端只写差异层；禁止为单个平台在网关层开特例分支。 |
| R3 | **能力三级标注** | 注册表以 core（全后端通用）／extended（多后端可用）／exclusive（单家独有、扩展形式保留）取代笼统的可用印象；exclusive 不是缺陷，是如实标注。 |
| R4 | **一致性即证据** | 「通用」只认一致性测试：同一动词、同一输入，在各后端的结果于预注册容差内等价，才准在该动词上用「跨平台通用」表述；平台整体不作此宣传。 |

## 二、原待拍板项 · 按通用化原则裁决（默认生效，鱼鱼保留否决权）

| 原条目 | 裁决 | 理由与做法 |
|---|---|---|
| D3 ogr2ogr 平台外通道 | **接，且升格**：GDAL/OGR 不称「平台外轮子」，登记为正式通用后端 `gdal`，与 postgis／qgis 同级治理（确认门、许可闸照套）；原 D3 三叶（PostGIS 文件级进出）改由 gdal 后端承接，账上如实标后端名。接入走 G4 契约包＋实机校准 | 格式转换本就是 GDAL 的通用本行；收编为后端比留作后门更通用、也更诚实 |
| D6 iServer 升正式后端 | **升**：iServer 按独立后端并网，以已登记的官方 MCP 通道为适配起点，走 G4 接入、逐叶校准放行；SuperMap 桥内不再硬凑服务面（原 V35/supermap 叶改标 iServer 后端待接入） | 服务面本就是独立后端问题；多一个同契约后端正是通用化 |
| D2 overlay 的 identity/update 合成 | **按合成做，且只写一份**：合成逻辑放网关通用层，PostGIS 以模板组合、QGIS 以算法拼装复用同一合成定义，账上标「网关合成」。先行核查：鱼鱼本机已装 QGIS 3.44.15，先查新版 Processing 有无原生同名算法，有原生则该侧不用合成 | 同一语义两处实现必然漂移，通用层单点定义才守得住 R1 |
| validate_repair 新接口（target 必填、输出新表） | **接受，并升为通用约定**：写入 G1 契约集（破坏类动词「原数据不动、输出新成果」），其余同类动词逐个对齐检查 | 该形态本身就是更通用的安全语义 |
| D1 nearest 模板并入正式模板集 | **并入**：builder＋列别名约定执行；且连接类模板的别名约定升为模板集通用规范，spatial_join 等同类模板一并对齐 | 已实测成立；通用规范防同类缺陷复发 |
