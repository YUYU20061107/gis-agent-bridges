# 实机校准指南 —— GeoServer 消费侧只读桥 v0.1 校准与收紧

这是一份结果式校准指南，交给在真实 GeoServer 上执行校准的
AI Agent：只描述要达成的结果、验收标准与红线，具体做法由
执行者决定；但每一步的原始输出必须留档回传，没有 JSON
原文的回报视为未执行。

前置环境：一台真实 GeoServer（本地部署或用户指定的测试
实例），一个有 REST 目录读取权限的账号（或已确认匿名可读
的实例），一份已知内容的图层清单。校准机上先跑通
`live/selftest.py`（协议自检 12/12）再进入实机步骤——自检
不过，先修协议层，不许往下走。

## 目标结果（全部达成才算完成）

1. probe_api.py 在目标实例全绿：版本号落档，工作区与图层
   计数与管理界面（或直接 REST 请求）一致（ready=true）。
2. 目录对账通过：list_workspaces / list_layers 的结果与
   同一时刻直接请求 `/rest/workspaces.json`、
   `/rest/layers.json` 的原始 JSON 逐项一致（数量、名字、
   类型）；超 300 条的实例须验证 truncated 标注真实出现。
3. 图层详情对账通过：任选一个矢量图层与一个栅格图层，
   layer_info 的 CRS、latlon 范围与管理界面图层页逐项
   一致；resource href 跟随行为与实例的实际 href 形态
   相符（若实例返回相对 href 或不同源 href，记录差异并
   按红线处理，不许放宽同源守卫凑绿）。
4. capabilities 对账通过：WMS 摘要的服务标题与图层名与
   原始 GetCapabilities XML 逐项一致；WFS 摘要同样对
   要素类型名完成一次对账。
5. 负例口径成立：错 token → BAD_TOKEN；无认证时 REST
   目录的 401/403 如实回报（不绕认证）；不存在的图层名
   → 结构化 404；非法图层名在发请求前被 BAD_NAME 拒绝。
6. 校准结论回写 README「状态声明」：环境与版本、逐项
   结果、与模板的差异点；selftest 保持全 PASS。

## 校准顺序（不要跳步）

1. **连通与版本**：配好 GEOSERVER_BASE_URL（与认证变量），
   跑 probe_api.py 并完整回传 JSON。ready 不为 true 就停
   在这里，先解决部署/地址/认证，不许往下走。
2. **目录对账**：对同一实例分别用桥与 curl（或浏览器）取
   原始 JSON，逐项核对工作区与图层；差异逐条记录。
3. **详情对账**：矢量、栅格各选一个图层，桥的 layer_info
   与管理界面逐项核对；特别核对 latLonBoundingBox 的轴
   顺序口径（GeoServer 历史版本有经纬顺序差异，记录原文
   不擅自换算）。
4. **capabilities 对账**：桥摘要与原始 XML 逐项核对，
   包括嵌套图层组（layer group）在 WMS 里的名字出现
   方式。
5. **负例验证**：按目标结果第 5 条逐项执行并留档。
6. **收紧与回归**：按实机差异改代码/文档口径（只许收紧，
   不许放宽硬上限或同源守卫来“适配”），跑 selftest，
   改动逐条回传。

## 红线

- 校准全程只许 GET 只读请求；不许为了对账去改实例的任何
  配置、图层或数据。样本图层须在桥调用之外准备并说明
  来源。
- 密码只经环境变量，不许出现在任何回传、日志或文件里。
- 对账参照值必须来自桥之外的独立来源（原始 REST 响应、
  管理界面）；拿桥自己的输出对账等于没校准。
- 任一步对不上：停在该步、回传差异，不许改判定口径凑绿。
