# 实机校准指南 —— GDAL/OGR 工具桥 v0.1 校准与收紧

这是一份结果式校准指南，交给在真实 GDAL 上执行校准的
AI Agent：只描述要达成的结果、验收标准与红线，具体做法
由执行者决定；但每一步的原始输出必须留档回传，没有
JSON 原文的回报视为未执行。

前置环境：一台装好 GDAL（版本落档，四件工具同版本）的
机器；校准素材全部用副本：一张数值已知的 GeoTIFF（如
已知像元值的 DEM）、一个要素数已知的 GeoJSON/Shapefile、
一个多图层数据集（如 GPKG）。校准机上先跑通
`live/selftest.py`（协议自检 15/15）再进入实机步骤——
自检不过，先修协议层，不许往下走。

## 目标结果（全部达成才算完成）

1. probe_api.py 全绿：四件工具路径、版本落档且同版本。
2. 栅格探查对账通过：raster_info 的驱动/尺寸/波段数/
   仿射变换与直接跑 `gdalinfo` 的原始输出逐项一致；
   投影 WKT 截断口径与原文核对无误。
3. 零副作用实测成立：对校准栅格跑 raster_stats 前后，
   原件目录的文件清单与原件校验值（哈希）不变，目录里
   不出现 `.aux.xml`；统计值与直接跑 `gdalinfo -stats`
   （在副本上、允许其写 PAM 的环境里）的结果一致。
4. 矢量探查对账通过：vector_info 的图层名、要素数、
   字段名与直接跑 `ogrinfo -so -al` 的原始输出逐项
   一致；多图层数据集逐层核对。
5. 转换对账通过：栅格转 GTiff 副本、矢量转 GeoJSON 后，
   输出能被 QGIS 打开（或经桥自己的 info 工具复核），
   尺寸/要素数与输入一致；字节级之外的内容差异（如
   GeoJSON 坐标精度）记录口径，不算失败但必须写清。
6. 负例口径成立：缺 confirm → CONFIRM_REQUIRED 且无
   输出文件产生；已存在输出 → OUTPUT_EXISTS；远程
   路径 → REMOTE_PATH_REJECTED；损坏文件 →
   GDAL_FAILED 原始报错如实回传。
7. 版本敏感点落档：本机 GDAL 版本下 `gdalinfo -json`
   的可用性、ogrinfo 文本形态与解析结果的差异点逐条
   记录（尤其老版本无 -json 时 PARSE_FAILED 的口径），
   校准结论回写 README「状态声明」；selftest 保持全
   PASS。

## 校准顺序（不要跳步）

1. **连通与版本**：跑 probe_api.py 并完整回传 JSON。
   四件不全绿或版本混杂就停在这里，先处理安装，不许
   往下走。
2. **探查对账**：按目标结果第 2、4 条逐项核对，参照
   值用你直接在命令行跑的 gdalinfo/ogrinfo 原始输出
   （不许经桥产生）。
3. **零副作用验证**：按第 3 条实测一次：跑前记录目录
   清单与原件哈希，跑 raster_stats，跑后复核并对账
   统计值。
4. **转换对账**：按第 5 条各转一份并复核。
5. **负例验证**：按第 6 条逐项执行并留档。
6. **收紧与回归**：若本机版本下模板有差异（-json 键集、
   ogrinfo 字段行形态），先记录差异原文，再改解析或
   文档；跑 selftest；把改动点逐条列清回传。

## 红线

- 校准素材一律用副本：不许拿唯一原件做任何一步，包括
  “只是读一下”的统计探查（零副作用要靠实测证明，不
  靠假设）；哈希对账的原件也放在副本目录里操作。
- 绝不覆盖这一条没有例外：转换目标永远选新文件名；
  不许为了重跑去删上一步的输出（需要清理时先留档
  清单、经用户同意）。
- 对账参照值必须来自桥之外的独立来源；拿桥自己的输出
  对账等于没校准。第 3 条的统计参照允许在副本上用
  原生 gdalinfo 产生（那正是桥外来源）。
- 任一步对不上：停在该步、回传差异，不许改判定口径
  凑绿。
