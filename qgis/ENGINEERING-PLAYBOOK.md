# 工程文件生产手册（QGIS / PyQGIS 版）

本手册把跨软件通用的工程文件纪律适配到 QGIS：通用教训来自 SuperMap 包
2026-10-24 的实机校准（详见 docs/CALIBRATION.md 的迁移一节），但 QGIS
专属结论**尚未实机验证**，文中标注「待实机验证」的条目按假设对待，
首次在真实 QGIS 上操作时逐项核对。先读本手册，再写一次性脚本。

## 1. 原件只读、先备份、只改副本

- 用户指定的原始工程（.qgs/.qgz）一律只读：任何写验证之前，先用
  无头桥 backup 生成带时间戳副本（回报 sha256），再复制出一份工作
  副本，只改副本。
- 全程核对原件修改时间（mtime）不变；变了就是纪律事故，立即停下回报。
- 实时桥的写/执行类工具（add_layer_from_path / run_processing /
  save_project）只许作用于工程副本，且必须经用户当场确认
  （confirm=true 不是 Agent 可以自填的开关；run_processing 的算法
  id 与参数须先给用户看过）。

## 2. 伴生文件完整性

- .qgs 是 XML 文本、.qgz 是装着 .qgs 的 zip，两者都不自带数据：
  工程引用的数据在工程文件之外。迁移/交付时要带上各图层数据源文件，
  尤其是 shapefile 一套件（.shp/.shx/.dbf 为核心，.prj/.cpg/.qpj
  尽量齐）、同名数据目录与 .gpkg/.sqlite 等单文件数据库。
- shapefile 缺 .shx 或 .dbf 等于数据损坏。scripts/verify_project.py
  会逐图层核对数据源存在性与 shapefile 核心伴生件，缺件记入 issues，
  如实回报，不要等 QGIS 打开报无效图层才发现。
- .qgz 交付前在新目录解开副本再盘点一次，确认 zip 内 .qgs 引用的
  相对路径在解出后仍成立。

## 3. 相对路径风险

- QGIS 工程的数据源大量使用相对路径（工程选项 projectPath 决定基准，
  常见形态 ./data/x.shp 或 ../shared/y.gpkg|layername=...）。相对路径
  以**工程文件所在目录**为基准解析，数据源字符串里 | 之后是图层名等
  参数，不是路径的一部分。
- 换目录、只拷工程不拷数据、把数据源挪层，都会让图层变无效
  （isValid=false）。先用 verify_project.py 定位缺失清单，再决定补
  数据还是修路径，不要自动改写工程 XML 里的数据源凑数。
- 数据库型数据源（PostGIS 连接字符串、虚拟图层、内存图层）不存在
  「文件缺失」一说：盘点里 datasource_exists=null 即属此类，如实标注。

## 4. 写后重读验证持久化（不信 API 返回）

- QgsProject.write() 返回 True 不等于改动已按预期落盘。通用教训
  （SuperMap 实机钉死）：存在「API 调用成功、内存对象已变，但保存
  后重开改动不在」的假成功路径；QGIS 上是否存在同类路径（尤其是
  经 iface 加入图层、图层树显隐这类经 GUI 状态的写入）**待实机
  验证**，因此一律按下面的规程验收：
  1. 写操作后对**副本**重新盘点（verify_project.py 或无头 inspect
     的 parse 策略），逐项核对改动（图层数、图层名、显隐、布局）。
  2. 需要确认实时状态时再开 GUI 打开副本抽查；导出类操作以文件
     真实落盘且字节数 > 0、能打开看内容为准。
  3. 重开后改动不在 = 本次写操作失败，如实回报，不许把 API 的
     成功返回当证据。
- 图层树勾选状态、画布范围等是 GUI/工程状态的一部分：只在内存里
  改了节点而没保存工程，重开必然丢失，验收必须走「保存后重开」。

## 5. GUI 刷新与无头边界

- 无头纯解析盘点看到的是工程文件里**已保存状态**；GUI 里未保存的
  修改盘点不到，不许把盘点结果说成界面现状。QgsApplication 无头
  打开同样看不到 GUI 会话。
- 实时桥（live:* 模式）才对应 GUI 里的当前工程；mode=file-fallback
  只是文件解析盘点，必须如实标注，不许冒充实时接入。
- 工具执行经 Qt 主线程调度（dispatch 字段）还是工作线程直执，
  决定稳定性边界：出现偶发崩溃或界面不刷新，先记录 dispatch 与
  复现步骤作为校准发现，不要连环重试。
- GUI 模态弹窗（未保存提示、算法参数窗）会阻塞主线程导致工具超时：
  先处理弹窗再重试。

## 6. 导出注意

- 三条导出策略（布局 QgsLayoutExporter / 画布 saveAsImage /
  QgsMapRendererSequentialJob 渲染）的真实签名与可用性因 QGIS 版本
  而异，**待实机验证**；以桥回报的 via 字段为准据实回报。
- 导出前确认输出目录存在；导出后核对落盘、字节数 > 0、能打开且
  内容是当前地图/布局（范围、图层齐全、布局元素不缺）。
- 布局导出显式记录 DPI 与页面尺寸口径；画布导出记录输出像素尺寸，
  不要用「导出了」三个字代替参数与证据。

## 7. 迁移验收规程（verify_project.py）

换目录、换机器、交付打包时按此顺序验收：

1. 原件先 backup（无头桥 backup 子命令，回报 sha256）。
2. python scripts/verify_project.py <工程.qgs|.qgz> --copy-to <新目录>
   脚本会连同主名伴生文件与各图层本地数据源一起复制，再对副本盘点：
   图层数、数据源存在性、画布 CRS、布局与原件盘点逐项对账。
3. issues 必须为空，或逐条有处置说明：数据源文件缺失与 shapefile
   伴生件缺失是最常见的两类；工程目录之外的数据源不会被复制，
   需人工随迁并在回报里列明。
4. 有条件时用 QGIS 打开副本抽查一遍界面，盘点 JSON 与界面证据
   一并留档。

## 8. 失败如实回报

- 一切失败走结构化报错（JSON + 退出码），回报附原始输出全文，
  没有 JSON 原文的回报视为未执行。
- 版本报错即停，回报原文，不许换版本、换环境反复试探；需要 QGIS
  的 Python 时用 QGIS 自带解释器，不要往无关环境里 pip 装东西凑。
- 桥返回 NOT_SUPPORTED / *_FAILED 并附现场方法清单是预期行为：
  把方法清单原样回传给维护者收紧，不要在实机临时发明新策略当定案，
  更不许新增 exec/eval 类任意代码执行入口绕过安全模型。
