# 工程文件生产手册（GeoScene Pro / arcpy 适配版，v0.2）

本手册把 SuperMap 桥 2026-10-24 实机校准沉淀的工程纪律迁移到 GeoScene 包：
原则是跨软件通用的工程文件纪律，API 细节按 arcpy 的形态写。
**本包与 GeoScene Pro 的兼容性是同源推断、尚未在真实 GeoScene Pro 上实机
验证**，手册中涉及具体 API 行为的条目均为待实机核验的假设（见
`docs/CALIBRATION.md` 新增一节），不要当作已验证结论引用，更不要拿
ArcGIS Pro 的结论冒充 GeoScene 的验证结果。

## 0. 先确认产品身份

- GeoScene 与 ArcGIS 共用 arcpy 内核：同一台机器上若两个产品共存，
  连错 arcpy 是最常见的误判来源。任何盘点、核验、交付之前，先核对
  preflight / `verify_project.py` 输出里的 product_clue
  （ProductName / InstallDir 原文）确属 GeoScene；身份不对就停下。

## 1. 原件只读：先备份，只改副本

- 任何写动作之前先用无头桥 `backup` 生成带时间戳副本（含同名 `.gdb` 整体复制
  与 sha256），一切修改只作用于副本；原件全程零写入，验收时以原件 mtime 未变
  为准。
- 无头盘点（`inspect` / `verify_project.py`）先把工程复制到临时目录再打开，
  不直接打开原件；实时桥的 file-fallback 同理，看到的是副本的存盘状态，
  界面不会刷新。

## 2. 伴生文件完整性

- `.aprx` 不是一个自包含文件：它引用的数据散落在同名 `.gdb` 文件夹、
  shapefile 与栅格文件里。迁移或打包时只拷 `.aprx` 一个文件，打开后图层
  大面积断裂是必然结果，不是工程损坏。
- shapefile 是多文件数据集：`.shp`（几何）、`.shx`（索引）、`.dbf`（属性）
  三者缺一不可；`.prj`（坐标系）缺失会让数据"能打开但位置不对"，
  `.cpg`（编码）缺失会让中文属性乱码。交付前逐个 shp 核对伴生是否齐全
  （`verify_project.py` 的纯标准库层会自动检查并写入 issues）。
- 文件地理数据库是文件夹（`*.gdb`），必须整体复制，不能挑文件拷。

## 3. 相对路径风险

- 工程可按相对路径存数据源引用：整个工程目录一起移动通常没事，
  只移动 `.aprx` 或改动数据目录名就会断链（图层 `is_broken=true`）。
- 盘点结果里数据源路径是工程文件中记录的路径，不代表当前机器上该路径
  真实存在；迁移验收必须在新目录重开盘点，逐项核对 `is_broken`，
  不能只看"工程能打开"。

## 4. 写后重读验证持久化（不信 API 返回，警惕假成功）

- 写类调用"没有抛错"不等于落盘成功。SuperMap 校准实测出现过专题设置
  "假成功"：包装对象改了、导出图与工程 XML 都没变。GeoScene 侧
  对应的高风险点（均为待实机核验假设）：CIM 定义回写后是否真的生效、
  `addDataFromPath` 返回对象与图层实际落位、保存后改动是否持久；
  且这些假设连"与 ArcGIS Pro 行为一致"本身都还没被证实。
- 纪律：每次写后必须重读验证——用 list 类工具复核状态；保存类操作后
  重开副本盘点核对改动仍在；导出类操作以目标文件真实落盘、字节数 > 0、
  能打开且内容正确为准。四者缺一，不许回报"成功"。

## 5. GUI 刷新与无头边界

- 无头模式只能看到上次保存到磁盘的状态（输出固定标注
  `mode: headless-saved-state`），永远不要把无头盘点说成界面实时状态。
- 实时桥在 GeoScene Pro 进程内操作当前工程，界面预期实时可见；
  file-fallback 是副本操作、界面不刷新，必须如实标注 mode。
- 桥在后台线程里调用 arcpy.mp：若实机出现线程异常或界面卡死，先停下
  记录回报，不要反复重试，更不要在实机临时改架构。

## 6. 导出注意事项

- 导出以"文件真实落盘"为唯一成功标准；调用未报错但文件不存在或字节为 0，
  一律算失败并如实回报。
- 分辨率（DPI）、宽高参数在 `Layout.exportToPNG` / `MapFrame.exportToPNG`
  上的真实签名在 GeoScene Pro 中是否与 ArcGIS Pro 一致，待实机核验；
  导出后要打开图片核对内容是当前布局/地图，而不是只看字节数。
- 输出目录必须预先存在；桥不会替你建目录。

## 7. 迁移验收用 verify_project.py

```
python scripts/verify_project.py --project <工程.aprx>
python scripts/verify_project.py --project <工程.aprx> --copy-to <新目录>
```

- 无参数 / 路径不存在 / 无 arcpy 时输出结构化 JSON 并以退出码 1 结束，
  不抛 traceback；`issues` 列表逐条列出断裂图层、伴生缺失、ZIP 结构问题；
  arcpy 层可用时输出还包含 product_clue，验收时先核对产品身份。
- `--copy-to` 验收流程：整包复制到新目录 → 对副本重开盘点 → 与原工程
  盘点结果逐项对比（地图数、图层数、断裂数、布局数）→ 原件 mtime 未变。

## 8. 交付前校验清单

1. product_clue 指向 GeoScene（不是同机共存的 Esri ArcGIS）。
2. 数据源数 / 地图数 / 图层数与任务预期一致，断裂图层为 0 或有书面说明。
3. 每个 shapefile 的 `.shx` / `.dbf` 齐全，`.prj` 缺失项已记录。
4. `--copy-to` 换目录后副本可打开、盘点结果与原件一致。
5. 导出 PNG 非空、能打开、内容正确。
6. 原件 mtime 全程未变；备份副本与 sha256 已留档。
7. zip 交付时包内文件齐全，能从压缩包解出后直接打开。

## 9. 失败如实回报

- 许可、版本、API 形态不符、产品身份不对等情况即停，回报原始报错全文
  与结构化 JSON，不换环境反复试探，不把失败粉饰成成功，
  不用临时发明的新策略冒充定案，不拿 ArcGIS Pro 的结果顶替 GeoScene 结论。
- 没有 JSON 原文的回报视为未执行。
