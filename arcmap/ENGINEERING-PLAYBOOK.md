# 工程文件生产手册（ArcMap / arcpy.mapping 版）

本手册把跨软件通用的工程文件纪律适配到 ArcMap：通用教训来自 SuperMap 包
2026-10-24 的实机校准（详见 docs/CALIBRATION.md 的迁移一节），但 ArcMap
专属结论**尚未实机验证**，文中标注「待实机验证」的条目按假设对待，
首次在真实 ArcMap 上操作时逐项核对。先读本手册，再写一次性脚本。

## 1. 原件只读、先备份、只改副本

- 用户指定的原始 .mxd 一律只读：任何写验证之前，先用无头桥 backup
  生成带时间戳副本（含 sha256），再复制出一份工作副本，只改副本。
- 全程核对原件修改时间（mtime）不变；变了就是纪律事故，立即停下回报。
- 实时桥的 save_document 只许对副本对应的文档调用，且必须经用户当场
  确认（confirm=true 不是 Agent 可以自填的开关）。

## 2. 伴生文件完整性

- .mxd 不是自包含文件：它引用外部数据源。迁移/交付时至少要带上：
  同名文件地理数据库文件夹（<原名>.gdb，须整体复制，不能只挑文件）、
  同主名旁置文件（如 .mxd.xml 元数据）、以及图层数据源指向的
  shapefile 一套件（.shp/.shx/.dbf 为核心，.prj/.cpg/.sbn/.sbx 尽量齐）。
- shapefile 缺 .shx 或 .dbf 等于数据损坏：盘点发现缺件要记入 issues
  如实回报，不要等打开报错才发现。
- 交付前用 scripts/verify_project.py --copy-to 把工程复制到新目录后
  对副本重开盘点，断裂图层（is_broken）与数据源缺失必须清零或逐条
  说明，才算迁移验收通过。

## 3. 相对路径风险

- .mxd 里的数据源路径可能是相对路径、绝对路径或 UNC 网络路径；
  相对路径以 .mxd 所在目录（及 ArcMap 的相对路径基准设置）为准。
- 换目录、改盘符、把工程拷到另一台机器，都会让相对/绝对引用失效，
  典型症状是图层 is_broken=true。先盘点定位，再决定修路径还是补数据，
  不要自动改写数据源路径凑数。
- 网络盘数据源在盘点时可能因断网误报缺失：回报时注明盘点环境，
  不要把环境问题说成数据问题。

## 4. 写后重读验证持久化（不信 API 返回）

- save() / saveACopy() 不抛异常不等于改动已落盘。通用教训（SuperMap
  实机钉死）：存在「API 调用成功、包装对象已变，但保存后重开改动
  不在」的假成功路径；ArcMap 上是否存在同类路径**待实机验证**，
  因此一律按下面的规程验收：
  1. 写操作后关闭并重新打开**副本**（或对副本跑 verify_project.py /
     无头 inspect），逐项核对改动（图层显隐、视图范围、文档属性）。
  2. 导出类操作以文件真实落盘且字节数 > 0、能打开看内容为准，
     不以 API 返回为准。
  3. 重开后改动不在 = 本次写操作失败，如实回报，不许把 API 的
     成功返回当证据。
- 文档对象是「当前文档」引用时，界面里的未保存状态与磁盘状态是
  两回事：回报必须写清核对的是哪一份状态。
- **2026-10-28 lab5 实测**：`saveACopy` 后关闭、重开副本、逐层打印
  `dataSource` 全部按预期更新，未观察到「API 成功但改动不落盘」的假成功路径。
  上面的规程继续保留（成本低、结论可信），但可把 ArcMap 这一条从
  「未知」更新为「本轮未复现」。

## 5. GUI 刷新与无头边界

- 无头盘点（inspect / verify_project.py）打开的是文件副本，看到的
  只有**已保存状态**（输出标注 mode=headless-saved-state）；GUI 里
  未保存的修改盘点不到，不许把盘点结果说成界面现状。
- 实时桥（live:* 模式）才对应 GUI 里的当前文档；mode=file-fallback
  必须如实标注，不许冒充实时接入。
- 视图级操作后界面是否即时刷新取决于 RefreshActiveView 是否命中；
  刷新失败不推翻数据结果，但要在回报里注明「界面未刷新，需手动刷新
  核对」。GUI 弹窗（未保存提示等）会阻塞主线程，先处理弹窗再重试，
  不要连环重试。
- 后台线程里调用 arcpy（COM 背景）是否稳定是本包最大的实机未知数：
  出现挂起或 COM 类异常，记为校准发现并停下，不要反复重试。

## 6. 导出注意

- ExportToPNG 的真实参数形态（PAGE_LAYOUT 字符串 / 数据框对象 /
  resolution 关键字哪条命中）因 Desktop 小版本而异，**待实机验证**；
  以桥回报的 via 字段为准据实回报。
- 导出前确认输出目录存在；导出后核对文件落盘、字节数 > 0、能打开
  且内容是当前文档（布局视图出整页、数据视图出当前范围）。
- 导出 DPI/分辨率按交付要求显式传参并记录在回报里，不要用默认值
  蒙混。
- **2026-10-28 lab5 实测补充**：真彩色被渲成蓝色的问题依旧，参数形态没有
  再验证（不值得再花时间）。实际做法改为「PIL 自绘合成 + 影像手工解码」，
  报告图与交付物一律不用 ExportToPNG 出图，并在给用户的说明里点明
  「这些是渲染图，不是 ArcMap 界面截图」。

## 7. 迁移验收规程（verify_project.py）

换目录、换机器、交付打包时按此顺序验收：

1. 原件先 backup（无头桥 backup 子命令，回报 sha256）。
2. python scripts/verify_project.py <文档.mxd> --copy-to <新目录>
   对副本盘点：数据框数、图层数、表视图数与原件盘点逐项对账。
3. issues 必须为空，或逐条有处置说明：断裂图层、数据源路径不存在、
   .gdb 未随迁是最常见的三类。
4. 在新目录里用 ArcMap 打开副本抽查一遍界面（图层能显示、范围正确），
   盘点 JSON 与界面证据一并留档。

## 8. 失败如实回报

- 一切失败走结构化报错（JSON + 退出码），回报附原始输出全文，
  没有 JSON 原文的回报视为未执行。
- 许可/版本报错即停，回报原文，不许换版本、换环境反复试探，
  更不许给普通 Python 3  pip 安装 arcpy（它随 Desktop 分发）。
- 桥返回 NOT_SUPPORTED / *_FAILED 并附现场方法清单是预期行为：
  把方法清单原样回传给维护者收紧，不要在实机临时发明新策略当定案。

## 9. 2026-10-28 lab5 实机复盘（详见 docs/LESSONS-lab5-20261028.md）

一次完整的无 GUI 实验任务（图形编辑 / 打断融合 / 属性编辑 / 拓扑检查）
把本手册里「待实机验证」的多数条目跑成了确定结论，并暴露出 12 条新的
10.8 边角。可直接固化为硬规则的是：

1. **arcpy 工作目录必须纯 ASCII**：中文路径会让 arcpy 把 UTF-8 字节按 GBK
   解释，报 `IOError: [Errno 2] ... 'E:\\ds\\xe5\\xb7\\xa5...'`，父目录中文同样污染。
   原件只读复制进 ASCII 目录作业，成果再复制回中文路径交付。
2. **OID 字段名一律用 `Describe(fc).OIDFieldName`**：迁移进 gdb 的要素类可能是
   `OBJECTID_1`，硬编码 `OBJECTID` 会删错要素（本轮真实踩中）。
3. **拓扑用 `da.Walk(gdb, datatype='Topology')` 枚举**，`ListDatasets` 在根级取不到，
   甚至返回 `None` 引发 TypeError。
4. **`ExportTopologyErrors` 判为不可用**（`ERROR 999999`），拓扑验收改几何解析三件套。
5. **交付 mxd 三段式验收**：包内同构目录 → 逐层 `replaceDataSource`
   （矢量 `SHAPEFILE_WORKSPACE` / gdb `FILEGDB_WORKSPACE` / **栅格 `RASTER_WORKSPACE` + tif 名**）
   → `relativePaths = True` → 重开逐层打印 `dataSource` 确认存在。
6. **无头不出界面截图**：成果图自绘（含影像手工解码），并向用户明确说明。
7. 小边角：`DeleteFeatures_management` 单参数、文本字段不写 `None`、
   进程内首次 `SearchCursor(SHAPE@)` 需 warm-up、`Dissolve` 后字段全丢、
   `replaceDataSource` 指向 gdb 要素数据集报 `Layer: Unexpected error`（改 RemoveLayer+AddLayer）、
   `arcpy.mapping.Layer(path)` 要求文件真实存在。
