# 实机校准指南 —— GRASS GIS 无头桥 v0.1 校准与收紧

这是一份结果式校准指南，交给在真实 GRASS GIS 上执行校准
的 AI Agent：只描述要达成的结果、验收标准与红线，具体
做法由执行者决定；但每一步的原始输出必须留档回传，没有
JSON 原文的回报视为未执行。

前置环境：一台装好 GRASS GIS 8.x 的机器，一个内容已知
的 location（有一张数值已知的 DEM 与一张矢量图层，参照
值来自 GRASS 之外或人工核对），工作 mapset 必须是数据
副本，不要直接在原始数据上校准。校准机上先跑通
`live/selftest.py`（协议自检 15/15）再进入实机步骤——
自检不过，先修协议层，不许往下走。

## 目标结果（全部达成才算完成）

1. probe_api.py 全绿：GRASS 版本落档，gisdbase 与
   location 清单与磁盘实际一致（ready=true）。
2. 只读对账通过：list_maps 与在 GRASS 里直接跑 g.list
   的结果一致；raster_info 的范围/行列与 r.info 原始
   输出逐项一致；location_info 的投影与默认区域与
   g.proj / g.region -p 的输出口径对得上（差异记录，
   不擅自换算）。
3. 作业对账通过：对已知 DEM 跑 slope_aspect，新图层
   真实出现在 g.list 里；坡度数值抽查与在 GRASS GUI
   或命令行直接跑 r.slope.aspect 的结果一致（同一
   区域设置下）。
4. 覆盖保护实测成立：故意用已有图层名做输出，作业必须
   失败（GRASS 拒绝覆盖）且原图层内容不变（抽查统计
   值与跑之前一致）。
5. 导出对账通过：导出的 GeoJSON 能在 QGIS 打开，要素
   数与 v.info 的计数一致，几何位置正确；对已存在路径
   的导出在调用 GRASS 前被 OUTPUT_EXISTS 拒绝。
6. 负例口径成立：缺 confirm → CONFIRM_REQUIRED 且
   GRASS 未被启动（以目标 mapset 无新图层佐证）；枚举
   外 job → BAD_JOB；不存在的图层 → GRASS_FAILED 原始
   报错如实回传。
7. 校准结论回写 README「状态声明」：环境与版本、逐项
   结果、与模板的差异点；selftest 保持全 PASS。

## 校准顺序（不要跳步）

1. **连通与版本**：配好 GRASS_BRIDGE_GISDBASE，跑
   probe_api.py 并完整回传 JSON。ready 不为 true 就停
   在这里，先解决安装/路径，不许往下走。
2. **只读对账**：按目标结果第 2 条逐项核对，参照值用
   你直接在 GRASS 命令行跑的原始输出（不许经桥产生）。
3. **作业对账**：按第 3 条跑一个作业并抽查数值；先
   记录跑之前的计算区域（g.region -p 原始输出留档），
   作业前后区域口径写清。
4. **覆盖保护验证**：按第 4 条实测一次重名输出，跑完
   复查原图层未被改动。
5. **导出对账**：按第 5 条导出并在 QGIS 验收。
6. **负例验证**：按第 6 条逐项执行并留档。
7. **收紧与回归**：若目标 GRASS 版本下模板有差异
   （g.list 输出形态、r.info -g 键集、--exec 行为），
   先记录差异原文，再改解析或文档；跑 selftest；把
   改动点逐条列清回传。

## 红线

- 校准只许在数据副本的 mapset 里做；不许动原始数据
  mapset，不许为了让作业跑通去改输入数据或区域设置
  （必须改区域时，先记录原区域、改动理由与恢复方式，
  并在回传中写清）。
- 绝不传 --overwrite 这一条没有例外：校准里需要重跑
  同一作业时，用新的输出名，或先经用户同意手工删除
  上次产物并留档。
- 对账参照值必须来自桥之外的独立来源；拿桥自己的输出
  对账等于没校准。
- 任一步对不上：停在该步、回传差异，不许改判定口径
  凑绿。
