# 实时桥设计说明（MapGIS）——只有设计，没有代码，且是刻意的

## 为什么 live/ 里没有 inapp_bridge.py

本系列其他桥的实时模式靠"应用内桥"：一段脚本跑在 GIS 桌面进程内，
拿到当前打开的工程，再开 localhost 服务供 MCP 客户端调用。这条路线
成立的前提是：**桌面软件存在可编程的当前会话接口**。

对 MapGIS 而言，这个前提**未经证实**：

- 没有公开文档证实 MapGIS Desktop 提供应用内脚本控制台或当前工程对象；
- Objects SDK 的 Python 绑定形态（模块名、入口）尚待探针回答；
- Desktop SDK 插件能否访问当前会话，未见公开说明。

写一段"假装能附着到 MapGIS 会话"的桥代码只会产生假结论。因此本目录
只放：本设计说明 + 探针版 MCP 服务端。探针结论（docs/CALIBRATION.md）
出来之后，按下面的路线决策再决定是否写实时桥。

## 三种候选路线与各自待证实点

### 路线一：Desktop SDK 插件进程内服务

形态：在 MapGIS Desktop 进程内加载一个插件，插件拿到当前工程/会话对象，
在 127.0.0.1 开带 token 的行分隔 JSON 服务；外部 stdio MCP 服务端转发
（与本系列其他桥的架构完全一致）。

待证实点（任一不成立则路线不通）：
- [ ] Desktop SDK 插件用什么语言开发（.NET / C++ / 其他）、如何部署？
- [ ] 插件 API 里有没有"当前打开工程/当前地图"的访问入口？
- [ ] 插件内能否起后台线程与 TCP 监听（桌面进程的沙箱限制）？
- [ ] 插件开发是否需要额外的厂商授权或付费 SDK？

### 路线二：Objects 组件嵌入（伪实时）

形态：桥进程自己嵌入 MapGIS Objects 组件，直接打开工程文件操作。
这**不是** GUI 会话接入：操作的是磁盘上的工程，GUI 里已打开的同一工程
不会实时变化（还可能有文件锁冲突）。若探针证实 Python 绑定可用，
此路线与无头桥合流，本质是无头桥的常驻服务形态。

待证实点：
- [ ] Objects 组件是进程内嵌入还是独立进程？许可何时校验？
- [ ] 组件打开 .MPJ 后，GUI 再打开同一文件是否冲突？
- [ ] 组件 API 是否覆盖盘点所需的工程/数据对象？

### 路线三：文件投递（最低配）

形态：Agent 把请求 JSON 投递到约定目录，由 MapGIS 侧的某种自动化机制
（宏/脚本/插件轮询）执行后回写结果 JSON。时效与可靠性最差，
只在路线一、二都不通且确有投递执行机制时考虑。

待证实点：
- [ ] MapGIS Desktop 有没有宏/启动脚本/定时任务之类的可编程触发点？
- [ ] 没有触发点则路线三不成立，不要用外部脚本假装它是。

## 当前可用：探针版 MCP 服务端

`live/mcp_server.py`（纯标准库 stdio）只暴露 3 个工具：

| 工具 | 作用 | 鉴权 |
|---|---|---|
| `mapgis_ping` | 服务端健康检查 | 无 |
| `mapgis_discover` | 探针结论摘要 | 须带 token |
| `mapgis_probe_environment` | 探针全量 JSON | 须带 token |

它不连接任何 MapGIS 进程，工具结果就是探针结果。token 约定与系列其他桥
一致：服务端启动时在 `~/.mapgis-bridge.token` 生成/读取 token，
受保护工具须在 arguments 中带对；将来若路线一成立，此约定平滑迁移为
桥侧握手token，不需要客户端改习惯。

接入前先跑 `live/selftest.py` 自检协议层（initialize / tools-list=3 /
ping / discover / bad-token，共 5 项，全 PASS 只说明服务端本身没坏，
不说明 MapGIS 可接入）。

注册方式：在你的 AI Agent / MCP 客户端的 MCP 配置中填
command 为任意 Python 3 解释器、args 为 `<仓库路径>/live/mcp_server.py`。

## 纪律

- 在探针结论支持之前，任何人不得宣称 MapGIS 已实现实时接入；
  向用户回报时必须区分"探针已证实"、"设计候选"、"未知"三档。
- discover 回报 `python_found=false` 是合法结论，如实上报，不许粉饰。
- token 不要发给任何人；探针 JSON 含本机目录结构，只回给维护者/用户本人。
