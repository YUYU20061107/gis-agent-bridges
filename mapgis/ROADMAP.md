# ROADMAP —— mapgis-bridge

## 当前状态：v0.1 探针先行（exploratory / unverified）

本包已交付：环境探针（核心）、无头骨架（preflight / backup / inspect 试探）、
探针版 MCP 服务端（3 工具）、实时桥候选路线设计说明。
本包未交付、且在探针结论出来前**不计划**交付：任何实时接入代码、
任何基于臆测 API 的业务工具。

## 决策门：探针结果 → 路线

实机探针（见 docs/CALIBRATION.md）的 JSON 回传后，按下表决策：

| 探针结论 | 决策 | 下一步 |
|---|---|---|
| 命中真实 MapGIS Python 绑定，且符号清单含工程/数据类入口 | **路线 A：无头桥做实** | 按探针符号清单收紧 inspect 为真实盘点（数据源/图层/要素计数），出 v0.2；实时路线另行评估 |
| 命中绑定但只有数据转换/格式级 API | **路线 A-：窄口径无头桥** | 只做盘点与格式盘点类工具，明示能力边界，不承诺工程级操作 |
| 桌面安装存在、Python 绑定不可用，但 Desktop SDK（插件）可得 | **路线 B：插件进程内桥评估** | 先证实插件 API 能否拿到当前工程会话（LIVE.md 路线一的待证实点），证实后才立项写插件桥 |
| Python 绑定与插件路线均不可用 | **路线 C：文件投递或搁置** | 评估文件投递（LIVE.md 路线三）是否有 MapGIS 侧触发机制；没有就如实搁置，在本文件记录结论，不硬做 |
| 关键未知：存在"当前会话"接口的直接证据 | 实时桥立项 | 按 LIVE.md 路线一/二细化设计，复用本系列的 token + confirm 纪律 |

## 待实机探针回答的问题（v0.1 的全部未知）

1. MapGIS 10 的 Python 绑定到底叫什么模块、装在哪、属于哪个解释器？
2. 绑定里有没有工程（.MPJ）打开入口？入口签名与返回对象形态？
3. MapGIS Desktop 是否存在当前会话/当前工程的编程接口（任何语言）？
4. Desktop SDK 插件的语言、部署方式与会话访问能力？
5. Objects 组件是进程内嵌入还是独立进程调用？许可校验在何时触发？
6. .MPJ 工程的数据组织方式：盘点一遍工程需要读哪些对象？

## 版本演进设想（全部以决策门结论为前提）

- v0.2（路线 A 时）：inspect 做实 + 探针候选清单按实机结果收紧、
  删除已证伪候选，命中策略写入文档并注明实机 MapGIS 版本。
- v0.3（路线 B 证实会话接口时）：实时桥设计定稿并实现最小工具集
  （ping / discover / 工程信息 / 图层清单，只读优先）。
- 任何版本都不做：许可绕过、原件写操作（无副本）、臆测 API 的工具。
