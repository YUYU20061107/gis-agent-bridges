# 实机探针执行单 —— mapgis-bridge v0.1

这是一份结果式执行单，交给在装有 MapGIS 的真实机器上执行探针的 AI Agent：
只描述要达成的结果、验收标准与红线，具体做法由执行者决定；
但每一步的原始输出必须留档回传，没有 JSON 原文的回报视为未执行。

注意：本包现阶段**没有实时桥可校准**，本执行单校准的是"探针本身"——
确认探针在真实 MapGIS 机器上能给出可信的肯定或否定结论。

## 前提

- 一台装有 MapGIS 10 系列桌面（Windows）且许可可用的机器。
- 知道 MapGIS 的安装目录；若 MapGIS 自带 Python 解释器，知道其路径。
- 本执行单全程只读：不安装任何包、不修改工程文件、不改系统环境。

## 目标结果（全部达成才算完成）

1. 探针在实机上完整运行并产出单行 JSON，结论明确：命中（exit 0，
   `found` 非空）或未命中（exit 1，`MAPGIS_PYTHON_NOT_FOUND`），
   两种结论都合法，不许为了"命中"而做探针之外的事。
2. 若机器上有多个候选解释器（系统 Python、MapGIS 自带 Python），
   每个解释器各跑一遍，每份 JSON 都回传并注明解释器路径与版本。
3. 若命中：`found.file` 的路径确实落在 MapGIS 安装目录内（不是撞名包），
   `found.top_symbols` 与 `found.classes` 完整回传，供维护者判断
   工程打开入口是否存在。
4. 若未命中：`install_dirs_found` 与 `module_attempts`（12 条尝试，
   含原始报错）完整回传，供维护者判断是"没装 Python 绑定"还是
   "绑定不在当前解释器路径上"。

## 执行顺序（不要跳步）

1. **记录现场**：MapGIS 桌面版本（帮助/关于界面）、安装目录、
   本机全部候选 Python 解释器路径与版本。
2. **跑探针**：每个解释器执行 `scripts/probe_mapgis.py`，保存完整 JSON，
   不要在终端里只看一半就下结论。
3. **交叉核对**：`install_dirs_found` 与第 1 步记录的实际安装目录对上；
   若探针说未命中但安装目录明明存在，把目录内与 python 相关的子目录
   结构（目录名清单即可，不读文件内容）一并回报——这能帮维护者定位
   绑定可能的位置。
4. **（仅命中时）无头骨架冒烟**：对一个可弃用的 .MPJ 副本先跑
   `mapgis_bridge.py backup`，再跑 `inspect`；inspect 无论命中入口还是
   返回 `NOT_SUPPORTED` 都完整回传 JSON。**只对副本跑，原件零接触。**
5. **（仅命中时）MCP 冒烟**：跑 `live/selftest.py` 应 5/5 PASS；
   再用 MCP 客户端调一次 `mapgis_probe_environment`，结果应与第 2 步
   同解释器的探针 JSON 一致。

## 每项验收标准

- 探针 JSON：`module_attempts` 恰好覆盖全部候选模块名，逐条有 ok/报错原文。
- 命中判定：`found.module` 已导入且 `found.file` 在 MapGIS 安装目录内；
  路径对不上的"命中"按撞名处理，结论记为未证实。
- backup：副本真落盘、sha256 非空、原件修改时间不变。
- inspect：回报里 opened_via 或 NOT_SUPPORTED 二选一明确，
  不许出现"大概能打开"式表述。

## 回报格式

①现场记录（版本、目录、解释器清单）；②每份探针 JSON 原文（注明解释器）；
③（如执行）backup / inspect 的 JSON 原文；④仍未回答的问题清单
（对照 ROADMAP.md 的六个未知逐条勾销或保留）。

## 红线（违反任意一条立即停下回报）

- **不装包、不改环境**：探针未命中不许 pip install 任何候选包，
  不许改 PATH/注册表"凑"命中；记录现象即可。
- **不编造**：不许猜模块名之外的"隐藏 API"，不许把其他软件的接口
  说成 MapGIS 的，不许删减尝试清单里的失败项。
- **原件只读**：一切冒烟只对副本；不许对正式工程跑 inspect 之外的动作。
- **许可问题即停**：出现许可类报错回报原文，不许尝试绕过许可。
- **探针 JSON 不外发**：其中含本机目录结构，只回传给维护者/用户本人，
  不许贴到公开渠道。
