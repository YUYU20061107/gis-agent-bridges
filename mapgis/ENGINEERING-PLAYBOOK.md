# 工程文件生产手册（MapGIS 探针优先版，适配版 v0.2）

本手册把 SuperMap 包 2026-10-24 实机校准沉淀的通用工程纪律，适配到
MapGIS 探针优先包。本包仍为 **EXPLORATORY / UNVERIFIED**：MapGIS 的
Python 绑定形态与“当前会话”接口均未经证实，本手册只约束工作方法，
不构成任何 MapGIS API 可用的断言。探针（scripts/probe_mapgis.py）的
JSON 结论永远优先于本手册的任何假设。

## 1. 探针先行（本包特有，第一步永远不变）

- 任何动作之前先跑探针并完整回传 JSON；探针未命中就停下，
  不进入 backup / inspect 之后的任何步骤，更不许自行装包凑环境。
- 探针命中也要核对 `found.file` 是否落在 MapGIS 安装目录内，
  路径对不上按撞名处理，结论记为未证实。

## 2. 原件只读，先备份、只改副本

- 一切试探只对副本做：先 `scripts/mapgis_bridge.py backup <工程.MPJ>`
  生成带时间戳副本（含同名数据文件）并回报 sha256，再对副本动作。
- 原件全程零写入：不 save、不删、不改；交付/回报时以副本清单与
  原件修改时间未变作为证据。
- backup 目标已存在时脚本拒绝覆盖，不要改名绕过，先查明原因。

## 3. 伴生文件完整性

- .MPJ 工程常伴随同名数据文件/目录；只复制 .MPJ 一个文件，
  工程可能打不开或盘点误报为空——复制与迁移必须带齐同主名伴生文件。
- `scripts/verify_project.py` 的文件层盘点会列出工程文件与同主名
  伴生文件的字节数与 sha256；伴生缺失要记入 issues 并如实回报，
  不许当作“工程为空”下结论。

## 4. 相对路径风险

- 工程文件内部对数据的引用可能为相对路径：换目录后打不开，
  多半是伴生文件没带齐或相对位置变了，而不是工程损坏。
- 迁移验收固定动作：`scripts/verify_project.py <工程.MPJ>
  --copy-to <新目录>`，对副本重新盘点（文件层 + 可用时的厂商层），
  副本结论与原件侧一致才算迁移成立。

## 5. 写后重读验证（不信返回、警惕假成功）

- 本包 v0.2 没有写业务动作；但未来任何写类能力立项后都适用本条：
  API 返回成功 ≠ 落盘成功，必须重开副本、重读结果核对后才许报成功。
- inspect 的“命中入口”只说明某个候选入口返回了对象，不等于盘点
  成功：v0.2 只回报打开策略与对象成员面，不解读语义、不编造
  图层/数据清单。全部策略失败就是 `NOT_SUPPORTED`，如实回报。

## 6. GUI / 实时边界（实时接口未证实，须如实写）

- MapGIS Desktop 是否存在“当前会话”接口**未经证实**；本包没有
  inapp_bridge，任何人不得宣称可实时操作 MapGIS（候选路线与各自
  待证实点见 live/LIVE.md）。
- 向用户回报时必须区分三档：“探针已证实”“设计候选”“未知”，
  不许把设计候选说成已实现能力。

## 7. 导出注意

- 本包没有导出类工具；探针 JSON 与盘点 JSON 就是本阶段的交付物形态：
  UTF-8、结构化、原文回传，不截断尝试清单里的失败项。

## 8. 迁移验收（交付前清单）

1. 探针 JSON 完整回传（含全部 module_attempts 与原始报错）。
2. backup：副本真落盘、sha256 非空、原件修改时间不变。
3. `verify_project.py` 对副本重盘：文件层清单与原件侧一致；
   无厂商绑定时结构化 `MAPGIS_NOT_AVAILABLE` + 退出码 1 是合法结论。
4. inspect（如执行）：opened_via 或 NOT_SUPPORTED 二选一明确。

## 9. 失败如实回报

- 找不到绑定报 `MAPGIS_PYTHON_NOT_FOUND`，打不开报 `NOT_SUPPORTED`
  并附尝试清单；许可类报错即停、回报原文，不许尝试绕过许可。
- 每一步的脚本原始 JSON 都要留档；没有 JSON 的回报视为未执行。
